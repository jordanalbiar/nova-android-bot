The splash page

first screen

The splash is the hologram stage you land on first, and on every launch: closing and reopening the app always lands here, never straight in the dashboard. The default layout is Minimal (v1.9): a clean centred stack, avatar directly over the bot name, then the status pill, the presence line and Enter dashboard, with the orbit buttons and stat bubbles as plain rows. Circles, Rectangles, Squares and Text-only are still in the Appearance picker, and a layout you picked stays respected; switching layouts never pushes anything out of the splash area. v2.1: Circles, Rectangles and Squares all keep the circular (orbit) pattern around the avatar, and only Minimal and Text-only stack. On a phone the splash reorders: orbit buttons and stat bubbles first, then Enter dashboard, then the avatar, status pill and Presence line below. At half screen size (the Razr front screen) the splash shrinks the hub, buttons and bubbles so everything fits without crowding or clipping. v2.2: in tall portrait the buttons sit in a left column and the stats in a right column, both in the top half, with Enter dashboard, then the avatar and Presence centred below; in mini mode (half screen) the buttons are left, the stats right, and the avatar and Presence are centred. v2.3: in tall portrait the buttons now run down the left edge and the stats down the right edge for the full height of the screen, the avatar is centred, Appearance and app settings sit above the avatar, and the status pill and Presence line sit below it. Appearance → Nova colour sets the colour for the active server, the dashboard accent, the avatar tint, embed-post themes and image covers for that server. A server with no colour of its own keeps its community-type colour (Gaming purple, Creative arts cyan, Development blue, Just for fun green, Communications grey); picking a colour for one server never changes another server's colour. It is not just a cover screen, and most of the dashboard can be peeked at, and some of it changed, without opening the full dashboard at all. v2.5: the status pill under the avatar now carries the activity type and presence text inside it (stacked lines, “● Online” on top, activity type below, presence text below that only when set), the separate presence line is gone, and the Appearance + app settings buttons above the avatar are gone, and both stay in the top toolbar. The name tag stacks three lines: “Discord bot”, the state word, and “serving …”. The avatar picker offers three separate preset images (full avatar, closer, closest face crop) instead of a zoom slider.

Tap the avatar to open the avatar window, change the avatar (the three choices are zoom levels of the same Nova avatar: Zoom 1 full, Zoom 2 closer, Zoom 3 closest face crop, or add your own from the gallery, and the zoom crop applies to it too), edit the display name, and update the presence from the side panel. The Enter dashboard button below the avatar opens the full dashboard. v2.6: saving an avatar preset also updates the bot's Discord avatar to that preset, and the window says whether it worked, and a failed update says why instead of claiming success. A gallery picture stays app-only and never touches the Discord avatar. Inside the dashboard, tapping the avatar again is the door back to the splash.

Left arc, quick-view windows (7)

Each bubble on the left opens a window over the splash with the real page content inside. Swipe sideways, use the arrow keys, or use Prev / Next to move between them, and they wrap around. Swipe down from the top, press Esc, or close the window to dismiss it. Every window ends with a link that opens the full page in the dashboard.

  • Overview, Key numbers
  • Command, Slash & text
  • Servers, Members & channels
  • Active users, Who's in the server
  • Activity, Recent events
  • System stats, Runtime info
  • Nova settings, Quick toggles

Each bubble on the right is a live headline number. Tap one and it expands into a full window with the detail behind the number.

Under the avatar

Status button

Opens Nova's Discord status editor right over the splash: online / idle / do not disturb / invisible, the activity type (Playing, Watching, Listening to), and the activity text. It is the same setting as the Presence tab, change it in either place and both agree, and it survives restarts.

Activity line

Under the status button sits a read-only line with the current activity type and status text (for example "Playing · helping in the server", or "Presence off"). Tap it, or the status button, to open the Presence window. The full Presence controls live on their own dashboard tab now; the splash no longer has an inline Presence module.

Switch server button

Shows which server the dashboard is currently looking at and opens the server list, with search. It is a view picker only: the bot is active in every server it is invited into, and nothing in the dashboard requires a server to be set first, and actions that need a server (Start fresh, channel builds, post batches) ask which server right there in the flow. With no server yet the button reads Add server instead and opens the add-server flow, paste the server id (Discord: Settings → Advanced → Developer Mode on, then long-press the server name → Copy Server ID), and invite the bot to that server with Administrator first.

Quick toggles

The Nova settings quick view carries on/off switches for Nova's modules, welcome, profile cards, tickets, role picker, YouTube, GIFs, News, moderation, GitHub, Asset Library, and the auto-restart check, so a module can be flipped without opening Config.

Documentation button

At the bottom centre of the splash sits the Documentation button. It pulls this guide in full screen over the dashboard (v2.3, it used to open in a small window), so help is one tap from the first screen, and you are reading it now.

Good to know: the splash is always a dark hologram stage, even if your phone is in light mode. The dashboard pages behind it stay on the same dark stage.

First open: a short guided tour walks through Plugins, Channel Setup, Post Setup, Image studio, Presence and Overview in seven steps, each with a More button for the fuller explanation. It runs once, replay it any time from the Documentation button below or from System.

Getting around

Dashboard layout

all pages

Open the dashboard and two toolbar rows frame every page, one under the other at the top of the screen. They do different jobs, mixing them up is the most common source of confusion, so here is the split:

Top toolbar, which page

The twenty-two page buttons: Overview, Config, Image studio, Image Library, Presence, Plugins, Posts, User posts, Commands, Servers, Channel setup, Templates, Post Setup, Post Generator, Users, Member list, Activity, System, DMs, Marketplace. Plus two conditional tabs that appear only while their plugin is on: GitHub (20th) and YouTube (21st). The page you are on stays lit white. Hovering any button washes it in the lighter logo blue. On phones the buttons show an icon with its label underneath. At the right end (its own full-width row on a phone) sits the server toggle (v1.5): the name of the server the dashboard is currently looking at, tap it to switch the view without leaving the page. It never blocks anything: actions that need a server ask in the flow. v2.5: the ☰ Pages button sits right of the Home button and opens the same Pages window as the splash ☰ button; the per-server pill strip under the tabs is gone, and switching lives only in the server toggle.

Second toolbar row, where on this page

Directly under the main toolbar (v2.3, it used to sit at the bottom of the screen). Not a second navigation. Its buttons are specialties for the page currently open, and they change when the page changes. Each one jumps straight to that part of the page and scrolls it into view; search specialties also put the cursor in the search box.

Always in the second toolbar row

  • Logo (left end of the second row), and the Nova mark lives here inside the dashboard.
  • Summary, which slides in a drawer with Nova's live summary: bot status, the active server's numbers, and when the data was last refreshed. On wide screens the summary sits beside the page instead.
  • ↻ Refresh, which re-reads everything live: Nova's process and log, her code, and the Discord API. Use it whenever a page looks stale. While it runs it reads Syncing…
  • Specialty buttons, the middle of the bar, specific to the open page (mapped per page in each section below).

Other layout habits

  • Home button, in the app's own top bar, immediately right of ← BACK, an icon-only 🏠 button (no text label) returns to the splash page from any dashboard page, the same destination as the Splash button in the second toolbar row. Back still closes the dashboard as before.
  • Collapse handles, and the small chevron button on each toolbar folds that bar away to a handle and brings it back, for more reading room.
  • Active server, and one server is active at a time. It is chosen on the splash (Switch button), from the server toggle menu at the right end of the top toolbar (v1.5, it shows the current server's name), or by tapping a server on the Servers page, and every page, plus every Config save, follows it.
  • Live, not a snapshot (v2.2), and the dashboard re-reads the sections that change (bot status, member counts, posts, stats) every few seconds and updates the page in place, without resetting your scroll, and the status bar shows a ● LIVE dot while live updates are running. A 60-second fallback poll covers a missed push, and ↻ Refresh still re-pulls everything on demand. DMs and Activity keep their own checks while open (see DMs).

Overview

tab: overview

The home page of the dashboard proper: the headline state of the active server and what changed last, in one screen. Inside the top toolbar, on every page, a status bar (v2.0) shows what the app is doing right now, loading / downloading / refreshing / synced, with a timestamp, and its ↻ Refresh now button re-pulls everything immediately. v2.2: the dashboard is live, member counts, posts and bot status update the moment they change, the status bar carries a ● LIVE dot, and a 60-second fallback poll covers a missed push. Modules no longer flash while you scroll: polls update only their status line and scroll position is kept.

Health

The top card is the HEALTH strip (v1.9): Token (Connected / Disconnected / Invalid), Bot (Online / Offline), Termux link (Linked / Not linked), Dependencies (node, curl, python3, Pillow, mirror, each OK / FAIL / unknown), and Admin for the active server, refreshed on sync, with a last-checked time. The token row never shows the token itself, not even masked characters, only the state word. Tap a failing row to jump to its fix: token → the System tab token entry, bot → the BOT tab, admin → the re-invite steps. v2.2: a dependency that has not been checked yet shows unknown, never counted as an issue; only a known failure counts. Tapping the Dependencies row offers Check dependencies, a fresh probe that reports each dependency's version with OK / FAIL / unknown (once installed, the BOT tab's Install dependencies button becomes Check dependencies and opens the same stats view). The splash shows the same as one compact line under the server bar ("✓ All systems go" or "⚠ 2 issues, tap to view").

What's new

The top card announces the current Nova version, version number, title, date, and the change list. The same version gets its own post in the 📊-updates channel in Discord; older version posts are never edited or removed. Dismiss the card with the × and only that version stays hidden, and the next version's card shows normally.

Integrations row

GitHub feeds

One row per tracked repo (triggerd, Creative-Canvas, vdo-portal): its channel, and whether its README is posted there. Nothing here polls on its own, and a repo is checked only when someone with admin rights types update in that repo's channel.

Asset Library

Approved count, how many submissions are waiting for review, and the two channels that matter: submit in #submit-your-asset, finished library in #asset-library. Categories run from 3D and Vector Files through Fonts, Audio, Code Snippets, and Templates.

Broadcast to all servers (v2.2)

One announcement, posted to every server the bot is in at once, from this page. Write the title and text, pick the colour and the target channel name (for example announcements), and the post goes to the channel with that name in each server. A server without a channel of that name is skipped and reported in the per-server results underneath, instead of failing the whole broadcast.

Dashboard stats (v2.2)

Who is doing what in the active server: top contributors by messages, most reactions, and voice time leaders, plus totals, messages, reactions, voice minutes, members. The numbers come from the file the bot writes on its 10-minute stats pass; until the bot has written it, the card says so honestly, "Stats not ready yet", instead of inventing numbers.

Key numbers

Twelve tiles for the active server: Servers, Members, Online now, Channels, Text · Voice · Categories split, Roles, Slash commands, Text commands, Open tickets, Warnings, Boosts, and Emojis · Stickers.

What Nova does

The bottom button opens the full feature list, every capability Nova currently has, counted on the button itself. Each item shows Live only when that feature is actually set up on the active server; a fresh server shows Not set up until it is configured, and Auto-restart always shows Not on phone, and the phone has no background restart check. v1.3 adds Roles, Clients, Member cards and Stats rows, and the GitHub feed row now reads On, no repos yet when the feed is on but no repo is configured. v1.4 lists all 29 functions in the same order as the Plugins tab, each with a status pill and a working toggle, in the same card layout as the desktop dashboard. The News row shows the feed count; the Moderation row shows whether the Moderator role is set.

Top-toolbar shortcuts: What's new · GitHub & library · Key numbers · What Nova does.

Config

tab: config

Where Nova is actually controlled. Config holds one settings record per server, and the form always shows the active server's settings, and saving writes only that server's record. Settings are stored in ~/discord-bot/nova-config.json on the VM and re-read every time Nova starts, so they survive restarts.

The module on/off switches (Welcome, Tickets, Role picker, YouTube, News, GitHub, Asset Library, Profile card) read the active server's plugin list, the same list the Plugins tab and What Nova does read, and apply immediately when flipped, without Save & apply. The other settings on each module still need Save & apply. Moderation and Auto-restart stay settings-file switches. GIFs is per-server since v2.1, and the switch gates /gif and !gif for this server.

Before you save: check the server named at the top of the form. If the wrong server is active, your changes land on the wrong server. Switch first (splash Switch button, or the Servers page), then edit.

How saving works

  1. 1
    Change a module. Use the module tabs on the left of the panel; the panel on the right is that module's settings.
  2. 2
    Save & apply (bottom of the page, or the Save & apply specialty button). The save writes the config file and restarts Nova so the new settings take effect.
  3. 3
    Wait for the refresh. The dashboard re-reads Nova after a short delay. If a picker looks empty right after a save, hit Refresh in the second toolbar row and try again.

Image studio

tab: studio

Design every image the bot posts, welcome covers, member cards, client banners, channel art, as builder cards with drag-and-drop layout editing. Image studio was a Config module until v1.8; it is a dashboard tab of its own now, server-scoped like Config (the top-right toolbar server switcher picks which server the designs belong to).

Surfaces

Tabbed by surface: Welcome covers, Member cards, Client banners (approved / revoked / reactivated), and Channel art (covers and banners). Each surface ships with a preset, headline, subline, accent and frame style already set for that surface, instead of the same generic default everywhere.

Editing a card

  • Headline / Subline / Accent / Frame style, the text and look of the card.
  • Artwork source, Built-in, Wireframe streaming template, Custom URL, or Off. The streaming template is an image option per surface and can be removed with Remove template.
  • Background image (v2.1), and the live preview shows the background image behind the headline and subline, so you see what the text will be generated onto. Edit background picks or replaces it, Remove background clears it. The background is stored on the design and saved with Save designs.
  • Edit layout, drag & drop, drag the text to move it, drag the artwork to pan it. Text size and Image zoom sliders, arrow keys nudge the text when the preview is focused, Reset layout restores the preset.
  • Channel covers and banners name the channel they go to, with a channel picker, pick one so the art knows where it belongs.

Designs are drafts on this phone. Save designs writes them to the bot's plugin-image-designs record; compositing them onto the bot's channel art still needs the web dashboard.

Top-toolbar shortcuts: Surfaces · Builder cards · Save designs.

Image Library

tab: library

Every cover and banner the bot has generated, in one list, and Image studio is where you make images; the Library is where you find, edit and delete them. Each row shows a thumbnail, the channel the image belongs to, whether it is a cover or a banner, and when it was generated.

Edit opens the matching builder card in Image studio (Channel art tab, with the channel already picked). Delete asks first, then removes the generated image from the phone, and the next seed for that channel falls back to the built-in default cover or banner instead of failing. The built-in default images themselves cannot be deleted: every channel's fallback depends on them. If the list is empty, nothing has been generated yet, generate one in Image studio, or run a Start fresh.

Presence

tab: presence

What the bot shows as its Discord status, show presence on/off, status (Online / Idle / Do not disturb / Invisible), activity type (Playing / Watching / Listening) and activity text. Presence was a Config module until v1.8; it is a dashboard tab of its own now, server-scoped like Config.

Off means invisible with no activity. The setting applies on the next bot restart, not immediately, and the bot only reads its config at startup. Save & apply sends it through the same path Config used and restarts the bot.

The same setting is shown in three places and they always agree: this tab, the splash avatar status line (read-only activity and status text under the online indicator, tap it to open the Presence window), and the side panel in the avatar window (tap the avatar on the splash). Change it in any one place and the others follow.

Plugins

tab: plugins

Every plugin stream the bot knows, on one page, grouped, Core, Content, Community, Moderation, each with an on/off switch. These switches control the active server and write the server's plugin list: the same list Config's module switches and Overview's What Nova does read, so all three always agree.

v1.4: Select all at the top of the tab, above the Core group, turns every plugin on; tapping again (Deselect all) turns them all off, through the same plugin list as the individual switches, so Overview and Config follow the bulk change.

v2.3: every plugin row also has an Edit button immediately left of its on/off toggle. Tapping it opens that plugin's config edit section, its Config module (Welcome, Messages, Profile card, Tickets, Roles, YouTube, GIFs, News, Moderation, GitHub, Starboard, Asset Library), the GitHub tab for the GitHub feed, the YouTube tab for Playlists, Post Setup for plugins whose editable surface is their generated post (Announcements, Discussions, Rules, Contact, member requests, Idea board, Watch requests, Sandbox, Create Your Own, LFG, Affiliates, AI tools, Activity log, Dashboard posts), or Channel Setup for Stats channels. Starboard is a new plugin in v2.3 (Community group): messages that earn enough ⭐ reactions get reposted to the highlights channel.

Clients opens Config → Tickets (request + admin review, like tickets); Bot messages log opens Config → Messages. No Edit button is dead, and every row lands somewhere real.

How the switches work

  • Stream switches apply immediately, no restart. Flip one and the bot's live gate for that stream changes.
  • Some plugins are also gated by a global master in the bot's settings, named on the row (for example welcomeEnabled, playlistsEnabled). The master is on by default; if it was switched off, the plugin stays off even with its stream on, and the row says so.
  • Moderation is a global master, not a per-server switch, and takes effect after a bot restart. GIFs is per-server since v2.1: the switch gates /gif and !gif for this server (a server with no setting uses the bot-wide default), and takes effect after a bot restart.
  • Playlists is one switch writing two streams (playlist panels + playlist cards). Its global master is playlistsEnabled, not youtubeEnabled, which only gates the /yt and !yt commands.
  • Moderation also needs the Moderator role in the server, and the row shows whether that role exists, and is gated per-guild by moderation.enabled (on by default).

Top-toolbar shortcuts: Core · Content · Community · Moderation.

Posts

tab: posts

Everything Nova herself has posted in the active server, and the tool to post more, in her voice, without opening Discord.

v1.4: the composer is tabbed, Embed (the builder below), Typography (themed text posts: Announcement, Notice, Rules, Minimal, and Discord has no rich fonts, so a theme is markdown formatting, with a live preview), and Poll (a real Discord poll: question, 2–10 answers, duration, multi-select). Images and button panels are not composed here, and images come from the bot's card renders, panels from /setup.

Embed builder (top of the page, for you only)

  1. 1
    Write it: title, description, and colour, pick from the swatch, type a hex value, or use a preset. Nova blue is the default. Optional fields can be added underneath.
  2. 2
    Check the live preview on the right, and it renders exactly the way the feed below renders real embeds, so what you see is what Discord gets.
  3. 3
    Pick the channel from the server's real text channels, grouped by category, and send. Nova posts it with her own credentials, and the feed re-reads so the new post appears in place.

Posts sent from the builder show up in the feed like any other Nova post, and can be edited or deleted from there.

The post feed

  • Load posts reads the last 100 messages in each of Nova's channels and forum threads in the active server. The header line reports how many posts were found, how many channels were read, and when.
  • Search and filter by text, and by kind, all posts, text, or embeds. Results group under channel headings.
  • Embeds render in full, the way they appear in Discord, not as raw data.
  • Edit / delete on any of Nova's posts: editing keeps embeds intact unless you actually change them; deleting removes the Discord message itself.
  • Members' own posts are not here, and they live on the User posts tab, grouped by channel with View / Edit / Delete, and per person on each member's card in Users.

Scheduled posts (v2.2)

At the bottom of the page: write the post now, pick the server and channel, the colour, and a date and time, and Nova posts it when the time comes. The list underneath shows every scheduled post as Pending, Posted or Failed (a failed one names its error), and a pending post can be cancelled. The bot checks for due posts every 60 seconds, so a post lands within a minute of its time.

Nova Poll (v2.3)

Below the composer sits the Nova Poll composer, a poll run by Nova herself, not a native Discord poll (the composer's own Poll tab is unchanged and still sends native Discord polls). Write the question, add 2–10 options, pick the channel to post the poll in, and pick where the results go: by default Nova auto-creates an admin-only #poll-results channel, so the owner can watch the results behind the scenes, or pick an existing channel instead. One vote per person, changeable, tap another option to switch your vote, tap the same option again to remove it. The status line says where the poll was posted and where the results will appear, or names the failure honestly.

Top-toolbar shortcuts: Embed builder · Nova Poll · Post feed · Search posts · Post sources · Scheduled posts.

User posts

tab: userposts

Every member's post in the active server, grouped by the channel it is in, the other half of the full sweep the Posts tab reads. The Posts tab is Nova's own posts plus the composer; this tab is everyone else's posts, and the tool to manage them. Post Generator stays the manual composer for one-off posts.

What you see

  • Grouped by channel, one section per channel ("#general (12)"), newest post first inside it, channels ordered by their most recent post. The category shows under the channel name where Discord reports one.
  • Search matches post text, author names and channel names; the list re-filters as you type.
  • Load posts (full sweep) re-reads the active server's channels and forum threads, the last 100 messages per channel, up to 400 posts. That is what "all posts" means here: everything in the last sweep. The header line reports how many channels were read and when the sweep ran.
  • Each post shows who posted it, when, whether it was edited or pinned, and whether it came from a webhook. Embed-only posts show their embed title; tap View for the full embed.

Managing a post

  • View shows the full post, text, embeds with fields, who posted it and when, with an Open in Discord link.
  • Delete asks first, then deletes the message in Discord. There is no undo, and the post leaves this list right away. A failed delete says why and nothing is removed.
  • Edit changes the message text. Discord only lets the bot edit its own messages, so editing someone else's post is refused by Discord, and the reason shows in the window instead of a fake success, and nothing changes. Embeds on the post stay as they are; only the text changes.
  • If a manage button says the action is not available in this build, the app bridge for it is missing, and the post itself is untouched.

How the data refreshes

snapshots

The dashboard reads stored snapshots, and, since v2.2, keeps them live: a live tick re-reads the sections that change (status, servers, members, channels, roles, activity, stats) every few seconds and updates the page in place, with a ● LIVE dot in the status bar and a 60-second fallback poll. Each full refresh still does a complete read and saves the result; pages display that saved state, stamped with the time it was fetched (see the Summary drawer). That design is why every page can say exactly how fresh it is, and why Refresh exists.

Glossary

terms
Active server
The one server the whole dashboard is currently pointed at. Chosen on the splash, on Servers, or in the dashboard's server toggle, and every page and every Config save follows it.
Snapshot
A saved, timestamped read of Nova's live state. Pages display the latest snapshot; Refresh takes a new one.
Specialty buttons
The second toolbar row's page-specific jump buttons. They change with the open page and scroll to a section (search ones also focus the search box).
Summary drawer
The slide-in panel behind the Summary button carrying Nova's live summary and the last-refreshed time.
Quick view
A splash window showing a page's real content without opening the full dashboard.
Module
One feature area inside Config (Welcome, Tickets, …) with its own on/off switch and settings.
Presence
Nova's Discord status: online state, activity type, and activity text. Edited on the splash or in Config → Presence, same setting both ways.
Gateway
Discord's live connection to the bot. A gateway drop is a disconnect; Nova reconnects, and drops are counted on Activity.
Intents
The permissions bitfield declaring which Discord events Nova receives (server members and message content are the notable ones).
Embed
A rich Discord message card, title, description, colour bar, fields. The Posts page's embed builder composes them.
Member / profile card
The wireframe card image Nova generates per member, posted on welcome, served by /profile, and editable from Member list.
Auto-restart check
The scheduled check that restarts Nova if her process dies. It logs events silently and never messages you about them.

Troubleshooting

help

A page looks stale or numbers look wrong

Tap ↻ Refresh in the second toolbar row and wait for Syncing… to finish. Pages show the last snapshot, so anything that changed in Discord since then only appears after a refresh. Check the fetched-at time in the Summary drawer if you're unsure which snapshot you're looking at.

A DM hasn't appeared

Open the DMs page and leave it open for about a minute, and it checks on its own, or tap Check for new DMs. DMs are not filtered by server, so the active server is never the cause.

Channel builds or Start fresh fail, or the app says the bot is not an admin

Check the server card on the Servers page: if it says "Bot is NOT Admin", the bot lacks Manage Channels / Manage Roles in that server, and every create fails. Give it Administrator in Discord (Server Settings → Roles, or re-invite it with Administrator, HELP section 4 in the app), then tap Check again on the card and retry. The pre-flight check runs before every build, so a build never starts blind.

A picker is empty (channel, member, generator)

The snapshot behind it predates the data. Refresh, wait, and reopen the picker. This shows up most right after a Config save restarts Nova.

My Config change landed on the wrong server

Config is per-server and always edits the active server. Switch the active server first (splash Switch button or the Servers page), confirm the name at the top of the Config form, then re-apply the change to the right server, and undo it on the wrong one if needed.

A member card image says it has expired

Discord signs image links for about a day. Refresh pulls in fresh links; nothing about the card itself is lost.

Nova shows “Not running” on System

Check Activity filtered to Restarts: the auto-restart check should have brought her back within its cycle and logged it. If she is still down after a cycle and Config → Auto-restart is on, the restart events in Activity are the record to look at first.

The Templates tab is empty, or says "Templates unavailable"

Empty with no message means nothing is saved yet, save the current server on that page and it shows up. "Templates unavailable: <reason>" means the list itself could not be built, and the reason is the diagnosis: a missing list script, unreadable template files, or a failed preset read. The same line is logged in the Activity tab. Tap Refresh and reopen the page; if the reason persists, it is a phone-side script problem, not a Discord one, and the theme templates on the same page can still be applied while the list is down.

The #dashboard channel in Discord looks different from this guide

That channel is a Discord-side companion, a banner, live stats, and a contents list posted by Nova. Two honest limits there: the banner is a placeholder card rather than a true screenshot, because the dashboard has no browser-openable address to capture; and its contents entries can't deep-link into specific pages for the same reason. This guide is the full documentation; the channel is the at-a-glance version.
